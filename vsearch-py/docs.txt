Distributed systems chunk logical entities into smaller pieces for parallelism and distribute those pieces across machines for fault tolerance.
A topic in Kafka is a named append-only log similar to a database table containing ordered event records.
Partitions in Kafka are physical chunks of a topic that serve as the unit of parallelism for producers and consumers.
Consumer groups in Kafka coordinate consumption where each partition is assigned to exactly one consumer in the group.
Kafka uses partition keys to guarantee that events with the same key go to the same partition maintaining order.
Messages in Kafka are retained for configurable periods enabling consumers to replay events by resetting their offset.
Log-based brokers like Kafka differ from traditional queues in that messages are retained rather than deleted after consumption.
OpenSearch uses inverted indexes that map words to document IDs enabling fast full-text search without scanning entire documents.
An index in OpenSearch is a logical collection of documents similar to a database table or Elasticsearch index.
Shards in OpenSearch are physical chunks of an index where inverted indexes are built enabling distributed searching.
The scatter-gather pattern in OpenSearch sends queries to all relevant shards then merges and re-ranks results from each shard.
Text fields in OpenSearch are analyzed for full-text search while keyword fields are exact-match and used for aggregations.
